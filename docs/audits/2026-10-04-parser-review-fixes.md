# Performance and Java parity review follow-up

This fixes the performance and Java-compliance findings from the review of
`14d7a2353102e7ebe3646fd581e1cad7afabdb66`. The earlier performance baseline is
`2b964abd62e0bd4b9abc9d450e369c72c095773f`; the Java reference is
`f32572b91b60690f6fb322156b471a290b23643e`.

## Changes

- Completed LN containment uses a union of inclusive intervals with tree
  lookup, preserving Java's handling of reversed and overwritten pairs.
  Previously every endpoint searched the entire completed-hold history.
- Immutable timeline and note state is retired after each measure. The parser
  retains the timing predecessor, rounded next-bar aliases, LNOBJ candidates
  and unresolved open-hold ranges. Arena collection is amortized so a long
  unresolved hold does not cause repeated copying of its whole history.
  Full charts keep stable public Note/Timeline pointers and detached partners;
  Scan does not retain the full graph. Unresolved holds can still require
  state proportional to their unresolved range.
- Default encoding detection follows Java's ordered charset round trips and
  64 KiB sampling/tolerance. Malformed UTF-8 replacement and default MS932/
  EUC-KR mappings follow the reference. Portable tables are generated by
  `scripts/encoding/GenerateJavaCharsets.java` using OpenJDK 25 mappings;
  no Java runtime is required to use the C++ library.
- `ChartMeta::VolWav` (default zero) and `Values` preserve `#VOLWAV` and
  case-sensitive `%`/`@` custom metadata, including Java's whitespace and
  skipped-branch handling.
- Authored `**` cells no longer create internal metronome notes. Generated
  ready measures continue to produce their clicks.
- The reference harness compares custom metadata and detached partner
  contents under four explicit RANDOM sequences. Timeline, partner and STOP
  microseconds are integers, avoiding hidden rounding above 2^53.

## Verification

- The new ordinary-chart memory-budget regression failed before the change
  at 119,582,028 bytes, then passed at 1,175,152 bytes for both Scan and
  metadata-only parsing. It parses 256,000 notes and checks an 8 MiB ceiling
  plus complete destruction. The input is allocated before measurement;
  this measures requested live C++ heap, not process RSS.
- Modular and amalgamated suites passed, including cross-measure LNOBJ,
  detached-head collection, long open ranges, synthetic ready clicks and
  ordinary metronome-token rejection. ASan, UBSan and float-cast-overflow
  verification passed.
- Before combining the encoding changes, 1,014 actual-Java chart comparisons
  passed. An independent streaming review compared roughly 28 million
  operations with the reviewed parser and checked 114 Java fixtures plus
  eight 1,000-measure charts with repeated collection and rounded aliases;
  no actionable production issue was found.
- Encoding work compared 131,584 legacy one/two-byte cases and 315,168 UTF-8
  samples with Java. The combined sanitized run passed 1,040 charts across
  four explicit RANDOM selections. A fresh run with integer-precision STOP
  and partner timestamps also passed all 4,160 comparisons under sanitizers.
  GCC 15 at `-O2` independently passed the same 4,160 Java comparisons.
- Final review identified the partner-time float conversion in the harness.
  Two regressions first reproduced lost one-microsecond distinctions above
  2^53 for partner times and STOP durations, then passed after integer parsing.

## Performance results

Measurements use Apple Clang 21, C++17 `-O3 -g0 -DNDEBUG`, one worker,
preloaded inputs and separate timing/allocation binaries. All 30 production
source hashes matched the tested snapshot before and after measurement.

| Scan input | Earlier baseline | Reviewed parser | Fixed parser |
| --- | ---: | ---: | ---: |
| 16k LN endpoints / 160 measures | 1.09 ms | 108.89 ms | 5.40 ms |
| 32k LN endpoints / 320 measures | 2.19 ms | 397.45 ms | 10.58 ms |
| 32k LN endpoints / one measure | 5.06 ms | 397.46 ms | 29.20 ms |
| 256k ordinary notes, peak live heap | 823,412 B | 119,582,212 B | 1,175,200 B |

Stress timings are medians of five rounds after warmup. Doubling LN endpoints
now takes 1.96x across measures and 2.16x within one measure. The 32k spread
case is 37.6x faster than reviewed; ordinary Scan peak live heap drops 99.02%.
The benchmark and regression executable have slightly different fixed overhead.
Allocation calls remain high (791,095 versus reviewed 789,622 and earlier
13,195 for the memory fixture); bounded live memory is not an allocation-count
reduction.

For 517 real charts (73,152,865 preloaded bytes), activity-filtered wall times:

| Mode | Earlier baseline | Reviewed parser | Fixed parser |
| --- | ---: | ---: | ---: |
| Full | 1,276.29 ms | 2,409.88 ms | 2,002.41 ms |
| Scan | 908.94 ms | 1,905.01 ms* | 1,512.94 ms |
| Metadata | 840.49 ms | 1,714.81 ms | 1,380.77 ms |

Entries are medians of three accepted post-warmup rounds except reviewed Scan
(*), where bounded retries yielded one activity-clean round. Simulator and
ReportCrash activity affected other attempts. Across all 12 reviewed Scan
rounds, wall/CPU medians were 1,908.04/1,906.65 ms; across nine fixed rounds,
1,512.94/1,511.16 ms. This supports roughly 20.7% Scan improvement with that
scheduling caveat. Full improves 16.9% and metadata 19.5% over reviewed.
**The fixed parser remains 1.57–1.66x slower than the earlier pre-parity parser
on this corpus.** The quadratic and unbounded ordinary Scan-state defects are
resolved; original throughput has not been fully recovered. The corpus is a
performance sample, not a measurement of how frequently each parity defect
occurs in real charts.

The same missing-base-BPM chart is excluded from all three versions. Timing
includes parser construction, hashing, parsing and destruction. Allocation
figures exclude preloaded input, allocator overhead and instrumentation headers.
Raw local evidence is in `/tmp/bms-perf-review-20261004/fixed-comparison.json`
and `fixed-findings.md`; source-manifest SHA-256 is
`5d459d9f25dad346d7692daa208f8457df49927a0eabc73f77e86800b3535195`.

## App integration handoff and limits

The user's instruction explicitly defers AsoBMaShow API/consumer changes.
All six findings and concerns are saved in its
`docs/audits/2026-10-04-bms-parser-api-handoff.md`: metadata invalidation,
PMS byte-format propagation, unpaired LN handling, saturated consumer timing,
mine recount, and historical replay compatibility. Another task is actively
working in that repository; this task does not alter its consumer code or
generated parser copies.

File-based PMS detection and byte-based BMS defaults therefore remain as
documented in README. Explicit C++ extensions (ready measures, metaOnly,
4K/6K/8K, SPEED, declared charset and derived statistics) remain outside Java
parity. Tests exercise explicit RANDOM choices, not equivalence of Java/C++
PRNG algorithms. These checks establish the covered behaviors, not proof for
every possible chart or application consumer.
