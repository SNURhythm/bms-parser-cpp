# Apple MD5 fingerprint backend

Starting revision: `10ad6470e0204db4d982059db603f8c82a860b33`, which already
contains ARM SHA256 acceleration. The parser uses Apple's system `CC_MD5`
one-shot routine on Apple platforms and retains the existing MD5 implementation
elsewhere. The helper is private to `Parser.cpp`; public MD5 streaming/string
interfaces remain unchanged. CommonCrypto is supplied by the system, so no
third-party dependency, linker flag or CPU-target flag is added.

The input is still the original bytes before text decoding. The previous
conversion to `MD5::size_type` is explicit, retaining its 32-bit length
narrowing. The result remains 32 lowercase hexadecimal characters. The native
call's deprecation warning is suppressed locally because existing BMS chart
identities require MD5. SHA256 and parser behavior are unchanged.

## Measurements

A fresh post-SHA Scan profile places MD5 at 16.57% of inclusive Scan samples
(1,014 / 6,120); SHA256 is 3.45%. This is a warmed 8-second sample on the
current Apple ARM64 host, not the earlier pre-SHA profile.

517 preloaded real charts, 73,152,865 bytes, one worker, seed 12345, Apple Clang
21 and C++17 `-O3 -DNDEBUG`. Each mode uses baseline/candidate/candidate/baseline
processes, one excluded warmup and six pooled measured rounds per variant.
All timings finished before production builds or pushes, with the self-hosted
CI worker absent and its listener idle.

| Mode | Starting CPU ms | Native MD5 CPU ms | CPU reduction |
| --- | ---: | ---: | ---: |
| Full | 1413.60 | 1375.60 | 2.69% |
| Scan | 952.51 | 911.29 | 4.33% |
| Metadata | 858.16 | 816.53 | 4.85% |

Wall-time reductions are 2.73%, 4.22% and 4.97%, respectively. These measure the
parser process on this host; they do not predict application-wide improvements
or improvements on platforms retaining the portable backend.

The native routine uses 52.35% more CPU time for empty microbenchmark inputs
and 14.41% more for 64-byte inputs. At 4 KiB and 1 MiB it uses 27.01% and
28.64% less CPU time, respectively. The corpus benefit is modest but
consistent across all three modes. No speculative small-input threshold is
introduced. Raw timings and pooled microbenchmark medians are in the linked
results below.

## Verification

- Clean modular/resource/Python-comparison and regenerated-amalgamation suites
  pass. Sixteen durable raw-byte fixtures check literal Python hashlib MD5 and
  SHA256 answers through Full, metadata and Scan paths, including NUL/high
  bytes and padding/block boundaries from 55 through 65,537 bytes. These new
  fixtures also passed against the starting parser before the change.
- Production hash and parser fixtures pass native Clang ASan/UBSan/
  float-cast-overflow and GCC 15 builds, both with `-Wall -Werror`.
- The complete generated parser compiles for macOS x86, iOS ARM64, and Android
  NDK 28.2 ARM64 default and SHA2-enabled targets. These are compile checks,
  not device-runtime tests; Android selects the existing MD5 fallback.
- The exact private helper passes 9,813 ASan/UBSan checks, including known
  answers, random binary data/chunks, offsets 0–31, empty/null input and explicit
  length-narrowing cases. This does not claim defined old behavior for enormous
  individual updates near the portable MD5 updater's unsigned loop boundary.
- 5,170 complete parser snapshots match the starting revision: 517 charts ×
  Full/Ready/Metadata/Scan/Scan-reference × two seeds. Snapshots include both
  original-byte hashes, timing, note structure and metadata.
- Independent static review approves the backend and durable parser fixtures.
